# Cross-Cutting Needs — Index

A **cross-cutting need** is an axis that can't be lost on its own — it's a property of *how* every other need is met. You're never simply "unfree"; you're unfree *in* the water arrangement, *in* the labour arrangement. So it's a lens run over every leaf, not a place in the tier tree. (Development-policy sense of "cross-cutting issue" — mainstreamed into every sector rather than run as one.)

**Test:** can you be deprived of it without simultaneously being deprived of some tiered need? No → cross-cutting. Yes → it's a tier, or a node.

Not a tier: no sub-needs, no override-frequency ordering, no `## How this need has been threatened` invariant.

## How a cross-cutting need is recorded

1. **Tag** — `cross_cutting: [autonomy]` on any tiered leaf where the axis bites. Renders as a one-line section on that leaf. No record here.
2. **Thin leaf container** — `cross-cutting/<axis>/<slug>.md`, only for failures that don't reduce to a single tiered need (slavery, bonded labour, totalitarian daily-life control). Same leaf schema (A–E) plus `tiers: [...]`.
3. **Essay** — the file below is the synthesis over both, and keeps the historical threat catalogue. Plays the `00-summary` role for its axis.

See `../../schema.md` → Cross-cutting need, and `../../data-model.yaml`.
